## 決定

### 以實機採集為主，模擬只做流程驗證

模擬場景不再追求和實機逐像素對齊。11/25 的新腕相機標定**不套用**到 MuJoCo／Isaac，場景檔維持現值。

依據：以實拍夾爪剪影比對（不經手臂 FK）：

| 腕相機位姿 + 鏡頭參數 | 乾淨影格 IoU |
|---|---|
| 現行場景檔（Menagerie 位姿 + fx 400、k1 −0.15） | 0.80–0.85 |
| Menagerie 位姿 + 實測 fisheye 內參 | 0.50–0.53 |
| Menagerie 位姿 + 實測 Brown 內參 | 0.22–0.26 |
| 手眼外參 + 任一內參 | < 0.03（夾爪落在畫面外） |

實測 Brown 與 fisheye 兩模型的留出誤差都約 1 px，但全畫面相差約 7° 的固定偏轉，代表光軸方向沒被唯一決定。手眼外參和 CAD 相機座差 36 mm、14°，且依賴暫定的關節映射。比對腳本與結果留在實機執行端的 `outputs/261125-camera/jaw-silhouette-check/`。

### 兩個固定姿態：停放位與通道位

- **停放位**：follower 靠在固定支撐上的收折姿態。所有解扭力都要先回到這裡。
- **通道位**：手臂離開收折區、位在工作區上方、腕相機沒有被遮住，同時當作標準起姿。
- 停放位 ⇄ 通道位是固定路線（教一次、回放）。收折區是最容易碰撞的路段（11/25 腕相機曾卡到 V 字支架），所以只走固定路線。其他動作都從通道位出發、回到通道位。

### 一筆資料的錄法（11/25 夜：從停放位開始，人工示範整段取放）

```
停放位（扭力開、leader 自動交接）→ [開錄] 出收折區 → 接近目標 → 閉爪 → 抬穩 → 搬到目的盤格位 → 張爪 → 退回起姿附近 [c 結束]
→（固定）起姿 → 停放位 → 解扭力
```

- 入口：`tools/lab_day.sh grasp`（終端按鍵，不用任務卡）。每筆按顏色鍵，同色多顆時從 D455 列出的編號選一顆（進階情境「指定哪一顆」的資料），再選目的盤；格位依序輪替（`configs/real_slots.json`，每盤 3 格、間距 70 mm，在可達的近端）。
- **只收粉盤 → 米盤**（決賽方向：粉盤存料、米盤交付格位）。`grasp` 預設目的地為米盤；反方向只在另行標記的資料集中錄，第一版訓練不混用。每筆之後由人把方塊放回粉盤的新位置。
- **夾錯或改單不搬回**：已放進米盤的方塊不再夾回粉盤；夾錯色或下單後改訂單時，由 LLM 在聊天框回報現況（已交付什麼、還缺什麼），等使用者決定。因此不需要米 → 粉的示範。
- **放置由人示範**，接在抬穩之後，不再先回起姿再走放開路線（那樣會來回走）。放開路線（`drop-*`）保留給 `--auto-place` 與備援。
- 目標座標：開錄第一張 D455（固定盤角 `outputs/<日期>-trays/trays.json`，手伸進盤也不影響座標系）。按 c 後再用 D455 看方塊實際落點與格位的距離。
- **不轉腕**：起姿路線與示範都維持初始腕角（腕相機支架曾因轉腕撞斷）。11/25 的示範 wrist_roll 仍有 20–35° 的轉動，要注意。
- 可達範圍（11/25 實測）：粉盤 x ≲ 100 mm 才穩；x 120 mm 時 elbow −74°，x 185 mm 時 −95°（極限 −97°）且夾不到。擺位與格位都放在近端。

### 控制頻率與訓練段（給訓練端，`feat/real-lerobot-training` 要跟著改）

- 30 Hz（本機 `single.local.yaml`）。11/25 五筆實測 29.9–30.1 Hz；相機在任務中只有單幀掉落（D455 最大 52 ms、腕相機 70 ms）。
- `review.json`（`outputs/<日期>-park/episodes/P*/`）：
  - `frames`：`start`（第一個動作前 5 幀）、`close`、`lift`（抬起後第一個靜止點），示範放置時再加 `release`、`end`。
  - `training_ranges`：`grasp = [start, lift]`；有放置時 `place = [lift, end]`。`training_range` 仍等於 grasp 段，相容舊轉換工具。
  - `target`：`d455`（開錄畫面的目標方塊：tray、x_mm、y_mm、yaw_deg、pixel…）；`place_target`：目的盤、格位編號與 `xy_mm`、D455 看到的落點。
  - `start_pose = "park"`：ACT 的夾取段從停放位開始。
- 訓練輸入建議：夾取 ACT 的 state 後面接 `[target.d455.x_mm, target.d455.y_mm]` 與 one-hot 的來源盤；放置 ACT 接 `[place_target.xy_mm]` 與目的盤。VLA 用語言（由 `task_card` 的顏色與目的盤產生）＋影像，整段使用。

## 下一步

採集端程式已備妥（假裝置驗證）：停放位 ⇄ 通道位路線、兩盤放開路線的教示（`real_route.py record-drop`）、合成採集 setup（`real_route.py setup`）、採集與重播的寬鬆動作規則、抬穩後自動放置。本機 `single.local.yaml` 已改為 30 Hz。

下次上機用 `tools/lab_day.sh` 逐步執行（每步一個指令，路徑與日期自動帶入；`FAKE=1` 可先用假手臂演練）。依序：
1. 教示並驗證停放位 ⇄ 通道位路線（`record`，再 `run`）。
2. 教示兩盤的放開路線（`record-drop --tray pink`、`--tray beige`）。
3. 以 `real_route.py run` 的 `t` 用 leader 試夾各區，刪掉候選擺位範本（`configs/real_collection.cards.template.json`）中夾不到的點，存成本次的 cards JSON。
4. `real_route.py setup` 產生 setup，開採集視窗，做空桌動作驗證。
5. 第一筆紅塊（粉 → 米）：從起始姿勢錄到抬穩，讀回後確認起點／閉爪／抬穩與 D455 目標座標，再做一次實機重播；檢查讀回報告的 `control_timing` 確認 30 Hz。
6. 通過後批次採集；收工時打包 session 給訓練端。訓練端說明見 `feat/real-lerobot-training` 分支的 `docs/real-training.md`。

### 跨位置泛化（給訓練端）

ACT 輸出絕對關節角，同一個「下降、轉腕、閉爪、抬起」在盤面不同位置對應的關節角不同。做法分三層：

1. **採集涵蓋位置**：任務卡改成每張卡一個位置（`make_cards`），120 筆約 120 個位置，不再是每個位置錄三色。範本為 20 mm 格、擺角 0°／30°／60°。相鄰位置以 60 mm 空間格歸成同一個 `layout_group`，`dataset_groups.json` 依群組切訓練／開發驗證，避免近似位置同時出現在兩邊。20 個保留擺位（`held_out.json`）不進訓練，用來測沒見過的位置。
2. **相對動作（請訓練端實作並比較）**：轉換工具加一個動作模式，把 `action` 改成相對該 action chunk 起點觀測狀態的關節位移，也就是 `action[t+k] − observation.state[t]`；部署時再加回當下狀態。原始 episode 不變，可和絕對動作並行訓練，以保留擺位的離線動作誤差與實機成功率比較。夾爪維持絕對開度可能較好，兩種都試。之後關節映射核對完，可再試末端座標位移。
3. **DAgger 補洞**：第一版在保留擺位與全盤格點評估後，針對失敗的位置或姿態用 DAgger 接手修正，再訓練。

## 對齊 main 的決賽情境（`docs/finals-shortage.md`、`docs/wrist-alignment.md`）

實機最終要跑同一套決賽流程（聊天下單 → 執行器選料 → 抓 → 放 → 核單；中途缺料時問改色或等補料），只是「下降、閉爪、抬穩」換成 ACT。對應關係：

| 模擬 | 實機 | 狀態 |
|---|---|---|
| 待命點（home），全局相機觀測、移除與補料都在這裡 | 停放位（ACT 每筆從這裡開始）；起姿只當放置後的過渡點 | 路線工具已有 |
| 選料：同色取離基座最近；進階情境指定某一顆 | 執行器從 D455 偵測清單選一顆，把它的托盤座標交給 ACT | `real_locate` 完成；採集時同色多顆可選編號，資料裡有「指定哪一顆」的條件 |
| 腕部定位 B + 下降、閉爪、抬穩 | 夾取 ACT（停放位 → 抬穩，以目標座標為條件） | 11/25 收了 5 筆試錄，4 筆成功 |
| 搬運、放置到米盤三個格位 | 放置 ACT（抬穩 → 格位放下 → 退回，以格位座標為條件）；放開路線為備援 | 格位定義 `configs/real_slots.json`；人工示範放置的流程已備妥，尚未上機 |
| 交付核對、掉落偵測（模擬真值） | D455：結束時看方塊在目的盤的落點與格位距離 | 已接進每筆的結果；決賽執行器尚未接 |
| 場景移除與補料 | 現場人員 | 由執行器回報待命停穩後才動手 |
| 夾錯色、交付後改單 | 不搬回；LLM 在聊天框回報已交付內容與差異，等使用者決定 | 聊天層要加這個回報（隊友負責）；手臂只做粉 → 米 |

接近與放置路徑都由人工示範，路線自然有差異即可。D455 粗座標的誤差（方塊頂面視差）由 ACT 透過腕相機修正。補料會放到「另一個合法位置與角度」，所以擺位要涵蓋不同位置與 yaw（不轉腕，夾爪對正方塊的面時由 ACT 學會在可接受的 yaw 內夾取；大角度的 yaw 若夾不起來，就限制補料角度）。

接上執行器時要新增實機後端：觀測（關節回讀 + D455 + 腕相機）、Pick = 夾取 ACT（目標座標）、Place = 放置 ACT（格位座標）、回待命點 = 起姿 → 停放位固定路線，並支援取消與原地保持。聊天與模擬流程的優化由隊友負責。

## 決賽策略更動（11/25，模擬端要跟著改）

實機手臂只學一種動作：從粉盤夾起、放進米盤的格位（`configs/real_slots.json`）。不會從米盤夾回，也不會放回粉盤。因此執行器與聊天層的策略要改成「不搬回，只回報」，模擬端（`docs/task-executor.md`、`docs/chat-layer.md`）要一起調整，讓兩邊行為一致：

| 情況 | 目前模擬端 | 改成 |
|---|---|---|
| 已鬆爪、數量超過新需求（多交） | 從放置盤把最後放的那顆取回來源盤（`retrieve_over_delivery`） | 不取回。帳本記「多交」，聊天框回報已交付內容與多出的顏色、數量，等使用者決定（例如接受，或由現場人員移除） |
| 夾錯色（核對時發現交付的顏色不在需求內） | 依多交處理並取回 | 同上：不取回，回報「放錯一顆某色」，等使用者決定 |
| 改單時手上夾著新需求用不到的積木 | 問「放回原位／放到指定位置／照樣送出」 | 只保留「照樣送出」（放進下一個格位並回報多交）與「停在原地等待」（夾著不動，等現場人員取下）。放回原位與指定位置需要粉盤放置技能，實機沒有 |
| 缺料（改色或等補料） | 照 `finals-shortage.md` | 不變。補料由現場人員放回粉盤 |

模擬端的驗收 `retrieve_over_delivery` 與 `hold_return` 要改成新的行為：只回報、不搬動，帳本仍正確。
