# 遙操作、資料與訓練

## 遙操作

所有輸入經 `InputProfile` 映射成[命令契約](interfaces.md#命令契約)，模擬與實機共用。

| 順序 | 輸入 | 內容 | 狀態 |
|---|---|---|---|
| 1 | Keyboard／mouse（EE） | 鍵盤控制 XYZ 增量；滑鼠控制指定平面位置與高度；另有夾爪操作。經受限 IK 轉為關節目標 | 預計實作 |
| 2 | SO-101 leader | leader 與模擬同機，經[本機輸入 adapter](interfaces.md#leader-輸入-adapter) 接入；接管與 reset 後對齊姿態 | 既有雙臂讀取與 JSONL 錄製／重播工具；單臂選擇與 adapter 預計實作 |
| 3 | Controller | 接到相同輸入介面 | 型號與映射待確認 |

EE 操作原則：

- 先固定可行的抓取方向，不要求 SO-101 達成任意六自由度姿態。
- 明訂操作座標系（相對桌面或基座），寫入 `InputProfile`。
- 不可達目標不執行；放開按鍵、視窗失焦或逾時停止增量。
- 關節鍵盤模式僅作除錯，不取代 EE 操作。

## Episode 資料

沿用既有實機記錄的 LeRobot dataset 格式（影像、狀態、動作、任務、時間戳），並補齊追溯欄位：

| 欄位 | 說明 |
|---|---|
| 影像 | 各相機串流，名稱與 policy manifest 一致 |
| 狀態／動作 | 實際關節狀態與命令動作，單位依 `RobotProfile` |
| 時間 | 每幀時間戳 |
| 控制來源 | 人工（leader／keyboard／mouse）或政策；既有 DAgger 以 `task_is_policy` 標記人工／政策幀 |
| 環境來源 | `real` 或 `sim`；sim 與 real 資料使用不同命名空間 |
| 版本 | 任務、場地、校正、政策版本 |
| 結果 | 成功／失敗、失敗與修正原因 |

隨機動作接線測試產生的資料不列為示範，不進訓練來源。

## 檢查與分割

訓練前逐一檢查：

- 完整性：episode 數大於 0、影像檔存在、幀數與時間戳連續。
- 對齊：影像與狀態時間對齊，動作單位與 `RobotProfile` 一致。
- 標記：控制來源分布合理、成功／失敗標記完整。

分割按**完整 episode** 與**未見配置**（例如未出現在訓練的積木位置或場地配置）進行，不在 episode 內切分。檢查結果與分割寫成資料 manifest（訓練／驗證清單與統計）。

## 訓練

| 項目 | 內容 |
|---|---|
| 主線 | ACT（LeRobot） |
| 技能範圍 | 局部操作：對準、下降、夾取、抬起；接近與搬運放置由幾何技能負責 |
| 輸入 | 腕部畫面中目標有一致相對位置；示範涵蓋多個關節狀態、盒內位置與姿態 |
| 前處理 | 若加入目標裁圖或遮罩，訓練與推論同步設計 |
| 首輪資料量 | 60–100 段短示範、10–20 段修正，依失敗分布調整 |
| 產出 | checkpoint、policy manifest（資料 manifest、相機前處理、正規化、訓練參數） |

標準 ACT 不預設理解顏色指令；顏色選擇由感知與任務執行器決定。

### 其他政策 adapter

| 政策 | 定位 |
|---|---|
| Diffusion Policy | 預留 adapter；既有實機工作區有訓練設定 |
| π0.5 | 替代方案，可評估 fine-tune；完整抓取政策與局部 ACT 技能範圍不同，替換時需調整執行流程 |
| Control Flow | 預留擴充，不是 ACT 基線的必要條件；接入時再取得對應程式與權重 |
| RL | 進階項目 |

既有實機工作區的資料與 checkpoint 來自雙臂衣物任務，不直接作為單臂積木政策或其訓練資料。
