# MuJoCo 決賽整單：中途缺料，改色或等補料

決賽缺料情境的模擬整合，本輪只做 MuJoCo。沿用 [#19](wrist-alignment.md) 的腕部定位、#20 的決賽流程、[任務執行器](task-executor.md)與[聊天層](chat-layer.md)。抓放沿用腳本化技能；ACT 的實機訓練另外進行。

## 情境

開場時，粉盤放缺料色 A 兩顆、優先色 B 一顆、替代色 C 一顆，米盤是空的。訂單是 A×2、B×1，B 先放。預設 A、B、C 是藍、紅、黃（決賽組合 2 藍 1 紅 1 黃），使用者說「兩藍一紅，紅色先放」。2026-11-22 的結果用的是舊預設紅、藍、黃與 `lab_20261120` 場景。

1. **先交付兩顆**：手臂先送 B，再送第一顆 A。每次放置都要核對過，帳本才加一。
2. **回待命點後移除**：第二筆交付核對後，手臂回待命點。手臂停穩、夾爪張開且是空的，場景才移除粉盤剩下的 A。米盤裡已交付的 B 與 A 留在原處。移除由執行器回報「待命停穩」這個狀態觸發，不是看經過幾秒。
3. **重新觀測再提問**：執行器不會被告知已移除，要自己重新觀測粉盤。
   - 看不清時，回報「看不清」並繼續觀測。
   - 確認 A 不在、C 還在，才透過聊天提問：「一藍一紅已放好，還缺一紅。要改成黃的，還是等你補紅？」
   - 場景事件只改變物理世界並留下紀錄，不會代替 agent 回答、改帳本或發缺料訊息。
4. **兩種回答**（同一個初始布局各跑一次）：

| 回答 | 手臂與訂單 | 結單條件 |
|---|---|---|
| 改 C | 剩下的一顆 A 改成一顆 C。回答後先重新觀測粉盤，以新影格確認 C 與它的位置，才只從粉盤抓 C | 米盤 A、B、C 各一，帳本相符 |
| 等補 A | 維持原訂單，停在待命點。執行器每秒看一次粉盤，看了 3 次後，場景把移走的 A 放回粉盤**另一個合法位置與角度**；執行器從新觀測定位，只補一顆 A | 米盤 A×2、B×1，C 仍在粉盤 |

使用者回答之前，兩條流程都保持等待。任何改單（包括接受替代色）都保留已交付數量，但讓先前的選料快照失效：下一次選料一定先取新觀測，看不清時複查，仍找不到就再回報缺料。等補料時跨過多個觀測週期，也不會再問一次、不會抓 C、不會提前結單。已交付的 B 和 A 不再搬動。

## 角色、布局與補回

角色寫在場景設定 [`configs/tasks/finals_shortage.yaml`](../configs/tasks/finals_shortage.yaml) 的 `finals.roles`：

- `shortage`：A；
- `priority`：B；
- `substitute`：C。

三色必須相異。場景依角色產生四顆積木 `[A, A, B, C]` 和訂單「B×1，再 A×2」。執行器從當次觀測建立候選清單，依剩餘需求選色，同色時選離基座最近的一顆。

**布局**用 [`configs/random_blocks_finals_20261125.yaml`](../configs/random_blocks_finals_20261125.yaml)（11/25 場景的粉盤近端；舊場景用 `configs/random_blocks_finals.yaml`）：

- 可達區、盤邊留白、含 yaw 的間距；
- 抓取 IK 檢查（四種 90° 朝向都試）。

四顆的顏色改由角色決定。四顆都平放在粉盤，各自抽 XY 與 yaw，其中兩顆同色。同一個 `seed` 永遠得到同一個布局。

**補回**由 `restock_pose` 抽樣，條件如下：

- 在粉盤內，留白與間距同上；
- 和當時盤內的積木保持含 yaw 的間距；
- 抓取 IK 可達；
- 離移除位置至少一個邊長加間距（29.5＋27 mm），yaw 至少差 10°。

米盤放置格位取自場景的 `placement_slots`（11/25 場景為實機採集的 4 格參考位置）；場景沒有設定時沿用 `configs/task.yaml`。

## 感知與控制來源

| 項目 | 來源 |
|---|---|
| 粉盤觀測（選料、缺料提問前） | 全域相機先看粉盤。遇到相關易混色或擬合不出的輪廓，腕部相機近拍。缺少需求色時，腕部掃描盤內四處複查。 |
| 回答「等補料」後 | 手臂留在待命點，只用全域相機定時看粉盤。若輪廓擬合失敗，或可能是需求色的積木仍有色彩歧義，回報看不清並等下一幀。新觀測清楚且找到需求色後才啟動抓取。 |
| 抓取位姿 | 相機。依觀測到的位姿接近，腕部拍第一張後移到腕部估計上方，再拍第二張（#19 B）；第一張沒確認時重新置中一次。同色時取離基座旋轉軸最近的一顆。 |
| 下降、閉爪、抬起、搬運、放置 | 腳本化技能，經共用 EE 控制器（IK、限速），只靠物理接觸。 |
| 交付核對、掉落偵測、提起檢查 | 模擬真值（`sim_truth`），與 #5 相同。 |
| 候選清單與物件 ID | 依相機估計的 XY，配對距離小於 25 mm 的最近可用模擬 ID，每個 ID 只配對一次。配對成功才加入庫存供選料；未配對的偵測留在觀測紀錄。抓取使用相機估計的 XY 與角度。 |
| 場景移除、補回、驗收評分 | 模擬真值。 |

場景設 `perception: sim_truth` 時，觀測與抓取位姿都改讀模擬器，只驗任務流程。

## 啟動

```bash
# 互動（主秀）：模型服務、模擬伺服器、聊天視窗；在聊天下單並回答
uv run tools/finals.py chat --roles blue,red,yellow --seed 12
#   聊天：「我要兩藍一紅，紅色先放」 → 等提問 → 「改成黃的」或「等你補藍」
# 單次（注入回答）
uv run tools/finals.py run --roles blue,red,yellow --seed 12 --answer substitute
uv run tools/finals.py run --roles purple,orange,dark_green --seed 21 --answer wait --video
# 驗收批次：三組角色 × 兩個 seed × 兩種回答 = 12 次
uv run tools/finals.py batch [--out outputs/finals/<名稱>] [--sets a,b,c;a,b,c] [--seeds 5,6] [--perception sim_truth]
# 場景預設 configs/scenes/lab_20261125.yaml，FINALS_SCENE=<場景檔> 可換
```

**各模式的行為**
- `run` 和 `batch`：開 MuJoCo 視窗執行，回答在缺料問題出現後注入，綁定該問題的 ID。
- `chat`：由 [`tools/lab.py`](lab-entry.md) 開好模型服務、常駐 MuJoCo 伺服器（`--task` 載入場景）和聊天視窗。訂單與回答都由聊天送出。

**重播**：每次執行都把完整場景檔寫在結果旁邊，同一個檔案可以重播：

```bash
uv run --with "opencv-python-headless>=4.9" scripts/mujoco_ee_teleop.py --scene configs/scenes/lab_20261125.yaml \
    --task outputs/finals/<批次>/<名稱>.yaml --exit_after_script
```

**輸出**（`<名稱>.*`）：

| 副檔名 | 內容 |
|---|---|
| `.yaml` | 場景 |
| `.json` | 檢查結果，以及 `finals` 紀錄：角色、移除與補回姿態、問題、回答、待命狀態 |
| `.jsonl` | 執行器與場景事件，`Ledger.replay` 可重建帳本 |
| `.csv` | 逐幀紀錄 |
| `.log` | 執行 log |
| `.mp4` | 錄影，只錄模擬器視窗 |
| `.chat.jsonl` | 聊天視窗的逐行紀錄，只有 chat 模式才有 |

批次另寫 `summary.json` 與 `summary.md`。

## 驗收檢查

每次執行除了 #5 的 `no_drop`、`no_stale_commands`、`skills_ok`，還檢查下表各項：

| 檢查 | 內容 |
|---|---|
| `priority_first` | 第一筆核對過的交付是 B |
| `standby_before_removal` | 移除前，手臂已在待命點停穩，夾爪張開且是空的 |
| `one_shortage_question` | 只問一次 |
| `question_content` | 缺 A×1、已交付 A、B 各一，替代候選含 C，選項只有改色與等待 |
| `no_pick_before_answer` | 提問到回答之間沒有開始任何抓取 |
| `delivered_untouched` | 已交付的積木核對後位移 < 3 mm |
| `final_placement`、`ledger` | 米盤與帳本符合該回答的結單條件 |
| 改 C：`substitute_untouched_until_answer` | 回答前 C 位移 < 2 mm（場景刻意移動 C 時，從移動後的位置算） |
| 改 C：`fresh_look_after_answer` | 回答到第一次 `pick` 之間有新的觀測；`pick.target.xy` 就是那次觀測到的 C；場景移過 C 時，目標離新位置 < 10 mm、離舊位置 > 一個邊長 |
| 等補 A：`substitute_stays_in_storage` | C 全程留在粉盤，位移 < 2 mm |
| 等補 A：`restock_new_pose` | 補回位置離移除處 ≥ 一個邊長加間距（56.5 mm） |
| 等補 A：`stays_at_standby_while_waiting` | 回答到下一次抓取之間，EE 位移 < 3 mm |
| 等補 A：`no_pick_before_restock` | 補回前沒有抓取，而且補回前至少觀測了 3 次 |

### 驗收：回答前移動替代色

`finals.move_substitute: true`（`tools/finals.py run|chat --move-substitute`）：缺料問題出現後、回答之前，場景把 C 移到粉盤內另一個合法、可達的位置。這個位置用和補回相同的條件抽樣，離原處至少一個邊長加間距。新位置不告訴執行器，要由相機取得。

## 限制

- 只在 MuJoCo 驗收；Isaac Sim 本輪暫停。
- 交付核對、掉落偵測仍讀模擬真值。放置後改用相機核對，留待之後。
- 全域易混的顏色規則來自模擬色票的渲染，換成實拍後要重新檢查。
- 若補回的顏色在全域畫面中持續有歧義，系統會持續等待。上述批次驗過的缺料色為紅、紫、青。
- 待命點是控制器的 home 位置；全域觀測時手臂不會擋到粉盤，這只在本場景確認過。11/25 場景的待命點取實機起姿的 xy，實機的待命是收折的停放位，模擬技能只能以垂直夾爪在 EE 空間移動，到不了收折姿勢。
- 11/25 場景的盤位依賴 11/20 的 D455 外參與暫定關節映射（`real_joints`）；逐軸核對與基座外參重量後要再更新。
